# jni-hello

Minimal JNI wrapper that embeds a sealed shadowvm bytecode blob and exposes two native methods to Java/Kotlin. Built so static analysts opening `libjni_hello.so` and `libshadowvm.so` in IDA Pro see only the opaque dispatcher + encrypted blob, not the arithmetic the DSL expressed.

## source

- `src/hello.sdl` - the DSL program (two helper functions plus `hello`)
- `assets/hello.svm` - the sealed blob (1228 bytes, embedded as `HELLO_SVM[]`)
- `src/hello_blob.h` - auto-generated byte array header
- `src/jni_hello.c` - JNI entry points
- `src/jni_hello.map` - version script that hides every symbol except the two JNI functions and `JNI_OnLoad`
- `android/HelloJNI.java` - the Java side

## build

```
cmake -S examples/jni-hello -B examples/jni-hello/build-arm64 ^
  -DCMAKE_TOOLCHAIN_FILE=%ANDROID_NDK%/build/cmake/android.toolchain.cmake ^
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-26 ^
  -DCMAKE_BUILD_TYPE=Release
cmake --build examples/jni-hello/build-arm64 -j
```

Output: `examples/jni-hello/build-arm64/libjni_hello.so` + the dependent `shadowvm` artifacts under `.../vm/`.

## regenerate the blob

```
PYTHONPATH=compiler python -m shadowc local examples/jni-hello/src/hello.sdl \
    --password hunter2 \
    --out examples/jni-hello/assets/hello.svm
python tools/svm_to_header.py examples/jni-hello/assets/hello.svm examples/jni-hello/src/hello_blob.h
```

## expected result

- `HelloJNI.runHello()` returns `((10 + 20) * 7) - 5 = 205`
- `HelloJNI.runSum(a, b)` returns `a + b`

## IDA Pro expectations

- `libjni_hello.so` exports only three symbols: `Java_com_trickhook_shadowvm_HelloJNI_runHello`, `Java_com_trickhook_shadowvm_HelloJNI_runSum`, `JNI_OnLoad`.
- Each JNI entry disassembles to a short wrapper that calls `svm_open_local` + `svm_run` + `svm_close`. There is no `add`/`mul` constant arithmetic visible.
- `libshadowvm.so` exports 8 names: `svm_open_local`, `svm_open_remote`, `svm_set_syscall`, `svm_run`, `svm_close`, `svm_strerror`, `svm_attest`, `svm_session_zero`. Every opcode handler is `static` + inlined into `svm_dispatch`; a static analyst sees one giant threaded-dispatch function and a decryption pipeline.
- The embedded `HELLO_SVM[]` buffer is encrypted (XChaCha20 + Poly1305, PBKDF2-hardened); without the password it is unopenable, and the password is itself inside the `.rodata` of the JNI wrapper - replace it with a server-released session key for production.
